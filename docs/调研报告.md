# MacBook 手风琴（MacAccordion）调研报告

> 调研日期：2026-09-22
> 本机环境：Mac15,12（MacBook Air 13" M3）/ macOS 15.7.9 (24G830) / Xcode 26.1.1

---

## 一、结论速览

1. **这个玩法确实存在，而且已经是一个小生态**——2025 年 9 月 Sam Henri Gold 开源了读取铰链角度的工具，之后衍生出至少 6 个"MacBook 手风琴"项目。
2. **本机传感器可用，已实测通过**。MacBook Air M3（Mac15,12）不在原作者的兼容列表里（他标注为"待确认"），但实测能正常读到 0–132° 的连续角度。
3. **不需要 root 权限**。只要用定向匹配的 `IOHIDManager` 打开传感器设备即可（有些项目要求 `sudo`，是因为它们走了另一条更重的路径）。
4. **关键实现细节有坑**：必须用 **Feature Report 轮询**，不能用 Input Report 回调——后者只有约 1 Hz 且静止时全是脏数据。
5. 复刻技术上完全可行，且本机工具链（Xcode 26.1.1 + swift + python3.13）齐备。

## 二、本机实测验证（第一手数据）

### 2.1 硬件存在性

```
$ hidutil list --matching '{"VendorID":0x5ac,"ProductID":0x8104,"PrimaryUsagePage":32,"PrimaryUsage":138}'
VendorID ProductID LocationID UsagePage Usage RegistryID  Transport Class
0x5ac    0x8104    0x0        32        138   0x100000794 SPU       AppleSPUHIDDriver
```

命中，传输层为 `SPU`（Sensor Processing Unit），且**无需 root 即可打开**。

### 2.2 数据格式（实测反推）

HID 报告描述符（179 字节）解析后，Report ID 1 的定义是：

```
Usage Page (Sensor 0x20), Usage (Orientation 0x8A)
  Report ID 1: Report Size = 9 bit, Count = 1, Logical Max = 360, Physical Max = 360
```

实际读到的 3 字节报告：`[report_id, 角度, 标志位]`

| 原始字节 | 解释 |
|---|---|
| `01 00 00` | 角度 0°（屏幕接近合上） |
| `01 85 00` | 角度 133°（屏幕接近全开） |
| `01 67 01` | **脏数据**（标志位非 0，角度字段不可信） |

**结论：`byte[1]` 就是角度（度），`byte[2] != 0` 时必须丢弃。**

### 2.3 30 Hz 轮询的实测曲线

以 30 Hz 轮询 Feature Report，请操作者缓慢匀速开合屏幕，得到 934 个样本：

```
0×192  359×14  0×2  1×3 3×3 5×2 6×3 8×2 10×3 12×3 15×1 16×2 18×2 19×3 21×2
23×3 24×3 25×2 26×3 27×3 28×2 30×3 31×3 33×2 35×3 37×3 39×2 41×3 43×3 45×2
... （单调递增）...
126×3 128×3 129×2 131×8 132×30 131×2 130×3 129×3 127×2 126×3
... （单调递减）...
9×3 8×2 7×3 6×3 5×2 4×3 1×1  0×301
```

- 上升段、下降段**完全单调平滑**，无跳变；
- `132×30` = 完全打开后保持约 1 秒的平台期（对应 MacBook Air 约 130° 的最大开合角）；
- 359 只出现在 `016701` 这一种形态，共 14/934 ≈ 1.5%，**用"丢弃 byte[2]≠0"一条规则即可干净剔除**。

### 2.4 一个重要反例：Input Report 回调不可用

同一台机器上，改用 `IOHIDDeviceRegisterInputReportCallback` + CFRunLoop（即 `macimu` 库的做法）：

- 回调频率只有 **约 1 Hz**；
- 屏幕静止时读数是 `016701`（359）和 `010000`（0）**交替跳变**，完全无法使用；
- 只有在屏幕运动中才偶尔给出真实值。

**所以：轮询 Feature Report（30 Hz）是唯一可靠路径**，这也正是 Sam Henri Gold 原始实现的做法。

## 三、传感器技术原理

### 3.1 硬件

- 传感器由 **SPU（Sensor Processing Unit）** 管理，在 IOKit 中以 `AppleSPUHIDDevice` / `AppleSPUHIDDriver` 出现；
- HID 标识：`VendorID 0x05AC`（Apple）/ `ProductID 0x8104`（Sensor Hub）/ `UsagePage 0x0020`（Sensor）/ `Usage 0x008A`（Orientation）；
- 引入时间：**2019 年 16 英寸 MacBook Pro**。此后大部分机型都有，但存在例外。

### 3.2 读取方式

```c
// 1. 用 IOHIDManager 定向匹配（只匹配这一个设备，避免触发"输入监控"授权）
matching = { VendorID: 0x05AC, ProductID: 0x8104,
             PrimaryUsagePage: 0x0020, PrimaryUsage: 0x008A };
IOHIDManagerSetDeviceMatching(mgr, matching);
IOHIDManagerOpen(mgr, kIOHIDOptionsTypeNone);
devices = IOHIDManagerCopyDevices(mgr);

// 2. 打开设备
IOHIDDeviceOpen(device, kIOHIDOptionsTypeNone);

// 3. 每帧轮询 Feature Report（30 Hz 足够）
uint8_t buf[8] = {0}; CFIndex len = sizeof(buf);
IOHIDDeviceGetReport(device, kIOHIDReportTypeFeature, 1, buf, &len);
// 角度 = buf[1]，若 buf[2] != 0 则本帧无效
```

### 3.3 机型兼容性

| 状态 | 机型 |
|---|---|
| ✅ 有传感器 | MacBook Pro 16" 2019（MacBookPro16,1 / 16,4） |
| ✅ 有传感器 | MacBook Pro 14"/16" 2021–2024（MacBookPro18,x / Mac14,5/6/9/10 / Mac15,3/6/7/8/9/11 / Mac16,1/5/6/7/8/9/10） |
| ✅ 有传感器 | MacBook Air M2 及之后（Mac14,2 / Mac14,15 / Mac16,12 / Mac16,13） |
| ✅ **有传感器（本项目实测）** | **MacBook Air 13" M3（Mac15,12）——原项目兼容表未收录，本机验证可用** |
| ❌ 无传感器 | M1 / M2 MacBook Pro（带 Touch Bar 的那代） |
| ❌ 无传感器 | 13" MacBook Pro 全系（MacBookPro17,1 / Mac14,7 / 15,2 / 15,4 / 16,2 / 16,3） |
| ❌ 无传感器 | 2019 年之前的 MacBook Pro、12" MacBook、所有台式机（iMac / Mac mini / Mac Studio / Mac Pro） |

### 4.3 共识与分歧

**所有项目一致的部分：**
- 传感器路径相同（0x05AC/0x8104 + UsagePage 0x20/Usage 0x8A）；
- 键盘映射都是"两排/三排字母键当钢琴黑白键"，布局高度趋同；
- 风箱模型都是"角度→音量，角速度→力度/音色明暗"。

**主要分歧点：**
| 维度 | 选择 A | 选择 B |
|---|---|---|
| 语言 | Python（快、好调参） | Swift 原生（低延迟、可打包、无依赖） |
| 传感器库 | pybooklid / hidapi | 原生 IOKit / macimu |
| 权限 | 需要 sudo（macimu 路径） | **无需 sudo**（定向匹配 IOHIDManager） |
| 音色 | 实时合成（锯齿波 + 失谐 + 气声） | SoundFont（.sf2）/ 外部 MIDI 音源 |
| 兼容策略 | 自适应归一化（自动学习行程） | 固定映射（要求机型一致） |

## 五、路线建议

### 路线 A：Swift 原生 App（推荐）
`IOKit HID 轮询 + AVAudioEngine 合成 + SwiftUI 界面`

- 优点：无 Python 依赖、可打包成 `.app` 双击运行、音频延迟最低、轮询频率不受 GIL 限制；
- 本机已具备 Xcode 26.1.1，可直接开工；
- 参考实现最全（MAcordion / maccordion / MaccorBook / simony3 Native 版）。

### 路线 B：Python 原型
`ctypes+IOKit（或 hidapi）+ numpy + sounddevice`

- 优点：改参数最快，适合先把"风箱手感"调舒服；
- 缺点：打包麻烦、音频回调受 GIL 影响、依赖多。

### 路线 C：Python 调参 → Swift 落地（混合）
先用 Python 把风箱模型和音色参数调好，再把验证过的数值搬进 Swift 原生版。

## 六、已知的坑

1. **Input Report 回调在 M3 Air 上不可用**（1 Hz + 静止脏数据）——必须轮询 Feature Report。
2. **`byte[2] != 0` 是脏数据**，不剔除会在曲线上打出 359 的尖刺。
3. **传感器读数是相对值**，不同机型基线和量程不同（本机 0–132，有的机型到 180+），跨机型必须做归一化。
4. **屏幕接近全合时会休眠**，实际可演奏区间约 30°–130°，下限要设死区。
5. **不要强推铰链**——所有项目都提示机械损伤风险。
6. 键盘监听若要全局生效需辅助功能授权；只在自己窗口内监听则不需要（MaccorBook 的做法）。

## 七、待确认的问题

1. 复刻的定位：**从零自己实现一版**，还是**基于某个现有项目改造**？若是后者，选哪个？
2. 技术栈：走 Swift 原生，还是先 Python 原型？
3. 音色路线：自研实时合成，还是用 SoundFont / 输出 MIDI 交给外部音源？
4. 是否需要 MIDI 输出（可接 GarageBand / Logic 的音色库）？
5. 目标机型：只服务本机（Mac15,12），还是要兼容更多机型？
6. 交付形态：本地自用，还是要打包分发？
